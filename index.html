Why VcsManager?

One portable contract for repository and pull request automation

Unified API

Create, list, get, and delete repositories. Create, list, get, merge, and close pull requests through one contract.

Four Providers

Use GitHub, GitLab, Azure DevOps, or Gitea without changing your application logic. Swap the package and configuration.

Modular Packages

The core package has no provider SDK. Install only the provider packages your application uses.

Pagination and Errors

One page shape with nullable totals and provider-driven next-page metadata. One exception family for every provider.

Operational Layers

Add retries, timeouts, concurrency limits, logging, and OpenTelemetry without modifying provider code.

Flexible Configuration

Configure with the fluent API, environment variables, or YAML. The last configuration source wins.

Configure Your Way

Register a provider, choose a configuration source, and build

  • Fluent API
  • Environment
  • YAML
Program.cs
using VcsManager;
using VcsManager.Builder;
using VcsManager.GitHub;

await using var provider = new VcsProviderBuilder()
    .WithGitHub(options =>
    {
        options.Token = Environment.GetEnvironmentVariable("VCS_GITHUB_TOKEN");
        options.DefaultOwner = "my-org";
    })
    .Build();

var repository = await provider.GetRepositoryAsync(new RepositoryRef
{
    Owner = "my-org",
    Name = "payments-api",
});

Console.WriteLine(repository.FullName);
Terminal
export VCS_PROVIDER=github
export VCS_GITHUB_TOKEN=<token>
export VCS_GITHUB_DEFAULT_OWNER=my-org

# In your C# code:
var provider = new VcsProviderBuilder()

    .Build();
vcs.yaml
# vcs.yaml
provider:
  github:
    token: <token>
    default:
      owner: my-org
Program.cs
var provider = new VcsProviderBuilder()
    .WithGitHub()
    .FromYamlFile("vcs.yaml")
    .Build();
